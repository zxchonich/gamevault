# CLAUDE.md

Этот файл содержит инструкции для Claude Code (claude.ai/code) по работе с кодом в этом репозитории.

## Проект

GameVault — курсовой проект на Django: веб-приложение для агрегации персональных игровых библиотек. Каталог игр с поиском и фильтрацией, личная библиотека со статусами прохождения, рецензии и оценки, профили пользователей, друзья и заявки в друзья, персональные рекомендации, заявки на добавление игр с модерацией, админ-управление играми и жанрами, синхронизация библиотеки Steam. Тексты интерфейса и комментарии в коде — на украинском.

## Команды

Запускать из корня репозитория в Windows (локально есть `venv/`):

```bash
venv\Scripts\activate
pip install -r requirements.txt     # обновлять через pip freeze > requirements.txt (сохранять в UTF-8)
python manage.py runserver
python manage.py check
python manage.py test library --keepdb                       # все тесты (~1-2 с с --keepdb)
python manage.py verify_email <логин>                        # вручную подтвердить email (без него вход паролем закрыт)
python manage.py sync_steam_all [--all]                      # синхронизировать устаревшие Steam-библиотеки (для Планировщика заданий)
python manage.py poll_steam_presence [--loop] [--force]     # опросить Steam «кто сейчас в игре» (--loop — постоянно)
python manage.py fetch_steam_achievements [--user <логин>]  # догрузить достижения Steam всех сыгранных игр
python manage.py test library.tests.test_steam --keepdb      # один модуль
python manage.py test library.tests.test_auth.LoginLogoutTests.test_login_success_rotates_session --keepdb
```

Линтер и форматтер не настроены.

Тесты (`library/tests/`) работают на MySQL, поэтому служба должна быть запущена. Таблицы приложения `managed = False`, поэтому [library/test_runner.py](library/test_runner.py) после создания тестовой БД загружает в неё [database/schema.sql](database/schema.sql) — при изменении схемы обновите schema.sql, иначе тесты разойдутся с реальной БД (с `--keepdb` после этого один раз запустите без него). Фабрики данных и `login()` — в `library/tests/base.py`. Настоящие HTTP-запросы в `GameVaultTestCase` запрещены (падают с AssertionError). Внешние вызовы Steam в тестах мокаются по месту использования (`library.views.moderation.fetch_store_details`, `library.views.catalog_admin.fetch_store_details`, `library.views.steam.sync_steam_library`, `library.services.steam_service._fetch_app_data`, `library.services.steam_service.requests`, `library.services.steam_presence._fetch_summaries`, `library.services.steam_achievements._fetch_schema` / `_fetch_player_achievements`).

## База данных

- MySQL (`game_library_db` на localhost:3306, utf8mb4). Параметры БД, `SECRET_KEY`, `DEBUG`, `ALLOWED_HOSTS` и `STEAM_API_KEY` читаются из `.env` (не в git; шаблон — [.env.example](.env.example)) через `python-dotenv` в [config/settings.py](config/settings.py). `db.sqlite3` не используется. Служба MySQL на этой машине (`MySQL96`) запускается вручную и требует прав администратора: `net start MySQL96`.
- Изменения схемы оформляются SQL-файлами в [database/migrations/](database/migrations/) (`001_steam.sql`, `002_...`), применяются к локальной БД, после чего [database/schema.sql](database/schema.sql) переэкспортируется: `mysqldump --no-data --skip-comments --set-gtid-purged=OFF --skip-add-drop-table` по таблицам приложения, затем убрать `AUTO_INCREMENT=N` и сохранить `INSERT` ролей. Репозиторий публичный: данные пользователей в git не коммитить.
- Структура таблиц задаётся [database/schema.sql](database/schema.sql), **а не** миграциями Django. Все модели в [library/models.py](library/models.py) имеют `managed = False` и явный `db_table`, а в `library/migrations/` миграций нет. Сначала загрузите схему в MySQL, затем `python manage.py migrate` — только для создания встроенных таблиц Django (sessions, contenttypes, admin, auth).
- Изменения схемы вручную переносятся в модель; `makemigrations` эти таблицы не изменит.
- `game_genres` в БД имеет составной первичный ключ (`game_id`, `genre_id`) без колонки `id`, хотя Django считает, что у `GameGenre` есть `id`. Создание/фильтрация/удаление через ORM работают, но не выбирайте и не агрегируйте `GameGenre.id` (например, `Count('game_genres')` падает — используйте `Count('game_genres__game_id')`). Жанры игры заменяйте через `selectors.set_game_genres(game, ids)`.

## Архитектура

Один Django-проект `config/` с одним приложением `library/`. Представления — функции в пакете [library/views/](library/views/), по темам: `catalog` (главная, каталог, страница игры), `library` (библиотеки, статусы, рецензии), `social` (друзья, профили), `accounts` (вход/регистрация), `moderation` (заявки на игры), `catalog_admin` (админка игр/жанров/рецензий), `discover` (рекомендации, лента), `steam`. Маршруты в пространстве имён `library:` в [library/urls.py](library/urls.py). Общие запросы и подготовка данных (фильтры библиотеки, статистика профиля, жанры, подписи статусов) — [library/selectors.py](library/selectors.py); валидация входных данных — Django Forms в [library/forms.py](library/forms.py) (HTML форм пока пишется в шаблонах вручную, форма только проверяет данные, `form.first_error()` даёт текст для шаблона). Подписи статусов в шаблонах — фильтры `status_label` / `status_label_other` (`{% load library_extras %}`).

**Аутентификация собственная, не `django.contrib.auth`.** `library.models.User` — неуправляемая модель над таблицей `users` с полем `password_hash`. При входе в сессию записывается `request.session['library_user_id']`; доступ и текущий пользователь — в [library/access.py](library/access.py): view помечаются `@library_login_required` (пользователь в `request.library_user`, иначе редирект на `library:login`) или `@admin_required` (не-админ получает `no_access.html`); там же `friend_ids`, `are_friends`, `can_view_profile` (приватный профиль виден только друзьям; тому, кого владелец заблокировал, — никогда) и безопасный `redirect_to_next`. **Чёрный список** (`user_blocks`, `UserBlock`; `block_user`/`unblock_user` в `views/social.py`): блокировка удаляет дружбу, заявки и уведомления между пользователями; заблокированный не может слать заявки, видит профиль и библиотеки блокирующего как закрытые (`private_profile.html`, «Заявки недоступні» — слово «заблоковано» ему не показывается) и не находит его в списке пользователей; события ленты скрываются в обе стороны (`hidden_user_ids`). `block_state(viewer, other)` → `"blocked"` / `"blocked_by"` / `None` передаётся в контекст для `friend_action.html`. Отклонённую заявку можно отправлять снова сколько угодно раз (старая удаляется), встречная заявка принимается сразу. Контекстный процессор [library/context_processors.py](library/context_processors.py) передаёт `current_library_user` во все шаблоны. В сессии также хранится отпечаток хеша пароля (`SESSION_AUTH_KEY`, `session_auth_hash`): после смены пароля все сессии, кроме текущей (`update_session_after_password_change`), разлогиниваются; входите только через `log_in()`, а в тестах — через `login()` из `tests/base.py`, который ставит отпечаток. **Подтверждение email:** аккаунт с паролем без подтверждённого email не входит (`access.needs_email_verification`; исключение — аккаунты, привязанные к Steam/Google). Регистрация и вход такого аккаунта ведут на `register/verify/` («Підтвердіть email», пользователь остаётся гостем, его id — в `session[PENDING_USER_KEY]`); ссылка из письма подтверждает email и входит. Письма и токены — [library/services/account_email.py](library/services/account_email.py) (подписанные `django.core.signing` данные, без таблицы; сброс пароля привязан к отпечатку хеша и одноразовый); новый email из настроек применяется только после подтверждения письмом. `User.email` может быть NULL (аккаунт из Steam) — сохраняйте `None`, а не `""` (уникальный индекс). Без `EMAIL_HOST` в `.env` письма печатаются в консоль runserver. Вход паролем — по логину или email. Смена пароля требует текущий пароль (если пароль у аккаунта есть); требования к паролю — `forms.password_problem` (от 8 символов, не только цифры, без логина, не из списка распространённых). Вход ограничен: 5 неудачных попыток на логин (20 на IP) за 10 минут — дальше 429 (`views/accounts.py`, счётчики в кеше Django; без `CACHES` это локальная память процесса, при нескольких процессах нужен общий кеш, а за прокси — правильный `REMOTE_ADDR`). Пароли хешируются через `make_password`/`check_password` из Django; оставшиеся пароли в открытом виде хешируются командой `python manage.py hash_plain_passwords [--dry-run]`. Не используйте `request.user`, `@login_required` или `django.contrib.auth.models.User` для пользователей приложения.

**Авторизация** основана на ролях из таблицы `roles`: `is_admin_user(user)` проверяет `user.role.name == 'admin'`; новые пользователи при регистрации получают роль `user`. Админские представления помечены `@admin_required`. Django-админка на `/admin/` — отдельная и работает через собственную аутентификацию Django.

**Действия, меняющие данные, — только POST.** Такие view помечены `@require_POST` (над декоратором доступа), а в шаблонах вызываются формой `<form class="inline-post-form" method="post">` с `{% csrf_token %}` и `<button class="link-button ...">`, а не ссылкой. `.inline-post-form` (`display: contents`) и `:where(.link-button)` в gv.css делают кнопку визуально идентичной ссылке, но обычно проще форма с `<button class="gv-btn ...">`.

**Ключевые моменты модели данных:**
- `Game` ↔ `Genre` — связь многие-ко-многим через `GameGenre` (`game_genres`). Хелперы `attach_visible_genres_to_*` в selectors.py прикрепляют к играм/записям ограниченный список жанров для шаблонов.
- `LibraryEntry` (пользователь + игра + статус), `Review` (оценка, используется для среднего рейтинга через `Avg('reviews__score')`), `SocialConnection` (отправитель/получатель со статусом `pending`/`accepted`; дружба проверяется симметрично через `are_friends`), `GameRequest` (заявки пользователей на добавление игр, одобряются/отклоняются в модерации), `DismissedRecommendation` (игры, скрытые кнопкой «Не цікаво»).
- `User.is_private` управляет видимостью профиля и библиотеки для тех, кто не в друзьях.
- Рекомендации считаются на лету в [library/services/recommendations.py](library/services/recommendations.py) (`build_recommendations(user, limit=None)`), в БД не сохраняются. Балл 0–100 = жанры (до 50: профиль вкусов из статусов, своих оценок и часов в Steam по играм каталога) + друзья (до 30) + качество (до 20, средняя оценка со сглаживанием к 6,5). Для пользователя без данных — запасной список популярных игр (`is_fallback`). Профиль вкусов (`build_taste_profile`) отдельно используется в профиле пользователя (`top_genres` — «Улюблені жанри»). Используется на `recommendations/` и в блоке на главной; число запросов не зависит от размера каталога (это проверяет тест) — новые сигналы загружайте пакетно, а не в цикле по играм.

**Вход через Steam/Google** ([library/services/social_auth.py](library/services/social_auth.py)): гость, вернувшийся из Steam (`steam/callback/`) или Google (`google/callback/`, [services/google_auth.py](library/services/google_auth.py) — OAuth code + PKCE + state, профиль из userinfo; `views/google.py`), входит в привязанный аккаунт или получает новый в один клик (`create_social_user`: логин из ника с суффиксом `_2…`, аватар провайдера, непригодный пароль, у Steam без email); вошедший пользователь тем же потоком привязывает провайдера. Google с почтой существующего аккаунта входит в него, только если там email подтверждён. Отключить провайдера нельзя, если это последний способ входа (`can_remove_login_method`; пароль считается способом только при подтверждённом email). Кнопка Google показывается, если заданы `GOOGLE_CLIENT_ID`/`GOOGLE_CLIENT_SECRET` (контекст `google_login_enabled`). В тестах Google мокается через `library.views.google.fetch_google_user`, аватары — `library.services.steam_service._download_image`.

**Уведомления** (колокольчик в шапке, `notifications/`) — таблица `notifications` и [library/services/notifications.py](library/services/notifications.py): заявка в друзья (`notify_friend_request`, исчезает при принятии/отклонении/отзыве — `forget_friend_request` и CASCADE по `connection`), принятая дружба, одобренная/отклонённая заявка на игру, друг запускает игру из библиотеки (`friend_playing`, создаётся в `steam_presence`, не во view). Создаются во view рядом с `activity.record_*`. Прочитанными становятся на странице уведомлений, кнопкой «Прочитати всі» и на целевых страницах (`friends`, `my_requests`, страница игры — `notifications.mark_read`). Счётчик и последние 8 — в контекст-процессоре. Текст одного уведомления — `components/notification_item.html` (глаголы в настоящем времени), время — фильтр `ago`.

**Автосинхронизация Steam:** `SteamAutoSyncMiddleware` на каждом запросе вошедшего пользователя вызывает `steam_autosync.maybe_autosync` — проверка кешируется на 10 минут, и если `ExternalAccount.last_synced_at` старше `STEAM_AUTOSYNC_HOURS` (6), синхронизация идёт в фоновом потоке с блокировкой в кеше. `sync_steam_library` сама обновляет `last_synced_at`. В тестах автосинхронизация выключена (`@override_settings(STEAM_AUTOSYNC=False)` на `GameVaultTestCase`); тесты автосинхронизации подменяют `_start` на синхронный `_sync_and_unlock`. Для расписания: Планировщик заданий Windows → задача раз в день, программа `venv\Scripts\python.exe`, аргументы `manage.py sync_steam_all`, рабочая папка — корень репозитория.

**Кто сейчас в игре (Steam presence)** — [library/services/steam_presence.py](library/services/steam_presence.py): Steam не шлёт событий, поэтому раз в `STEAM_PRESENCE_INTERVAL` (60 с) `poll()` спрашивает `GetPlayerSummaries` (до 100 steamid за запрос; `gameid`/`gameextrainfo` есть только у тех, кто в игре; не-Steam ярлыки — 64-битный gameid → `appid = NULL`, только название). Из ответов строятся `PlaySession` (`play_sessions`; открытая — `ended_at IS NULL`): новая игра — сессия + уведомление `friend_playing` друзьям, у которых игра в библиотеке (`notify_friends`, кулдаун 12 ч); та же — `last_seen_at`; пропала/сменилась/нет опросов дольше `CONTINUE_GAP` (30 мин; та же игра после более короткой паузы, например перезапуска сервера, — та же сессия) — сессия закрывается на `last_seen_at`; «в игре» показывается только при опросе не старше `STALE_AFTER` (5 мин), в ленту пишется `play_session` (сессии одной игры за день суммируются, `status="first"` — первый запуск), при ошибке Steam ничего не закрывается. Запускают опрос: фоновый поток `steam-presence-loop`, пока работает runserver (`start_background_poller` из `LibraryConfig.ready`, только в дочернем процессе автоперезагрузки — `RUN_MAIN`), запасной — `SteamAutoSyncMiddleware` (`maybe_poll`, тик в кеше) и команда `poll_steam_presence --loop` (без сервера); двойной опрос из разных процессов исключён атомарным UPDATE строки `app_state` (`claim_poll`). «В игре» показывается только друзьям и себе и только для свежих сессий (`live_sessions`, `live_for_users`/`attach_live`, `live_in_game`): блок «Зараз грають» на главной и в ленте, чип в профиле, карточки друзей, «Друзі з цією грою». Настройки пользователя: `show_playing_now` (статус и уведомления друзьям), `notify_friend_playing`; события сессий в ленте подчиняются `show_activity`. В тестах опрос выключен (`STEAM_PRESENCE=False` на `GameVaultTestCase`), тесты middleware подменяют `_start` на `_poll_and_unlock`.

**Достижения Steam** — [library/services/steam_achievements.py](library/services/steam_achievements.py): схема (название, описание, иконка, редкость из глобальных процентов) — один раз на appid в `steam_achievements` + метка `steam_achievement_schemas` (`total = 0` — достижений нет); полученные — `user_achievements`; прогресс в игре — `ExternalLibraryItem.achievements_unlocked/total/checked_at`. После каждой закрытой сессии (`process_pending_sessions` в конце `poll`) достижения игры обновляются, а полученные в окне сессии попадают в ленту событием `achievements` (за день суммируются); `backfill` в каждом опросе догружает несколько сыгранных игр без событий в ленте (старые достижения не спамят). Показ: страница игры («Ваші досягнення», прогресс и самое редкое), профиль («Останні досягнення», счётчик), карточки Steam-библиотеки, иконки в событии ленты. При отвязке Steam достижения удаляются.

**Достижения GameVault** (свои значки сайта, не путать со Steam) — [library/services/site_achievements.py](library/services/site_achievements.py): определения в `ACHIEVEMENTS` (ключ, название, категория, иконка из `ICONS`, пороги уровней — 3 порога = бронза/серебро/золото, 1 порог = одноразовое; `secret=True` — до получения «???»). Прогресс считается на лету (`compute_metrics`, только для незавершённых), в БД — лишь полученные уровни `user_site_achievements` (`UserSiteAchievement`). `check(user)` вызывается из `activity.record_*` (`_check_achievements`, через `check_quietly` — ошибки не ломают действие) и при открытии своего профиля/страницы достижений; первый подсчёт пользователя (`users.achievements_synced_at IS NULL`) тихий — без уведомлений и ленты; новым пользователям `achievements_synced_at` ставится при регистрации. Дальше на каждое поднявшееся достижение — уведомление `site_achievement` и событие ленты `site_achievement` (`achievement_key`, уровень в `item_count`). Страницы: `achievements/`, `users/<id>/achievements/` (по правилам `can_view_profile`), редкость — % пользователей сайта. Витрина в профиле (`components/showcase.html` + `static/library/js/showcase.js`: перетаскивание pointer-событиями, выбор кликом, до 5): `users.achievement_showcase` — ключи через запятую, NULL — автоматически (высший уровень, редкость, новизна); сохраняет `save_showcase`. Значок — тег `{% site_badge key tier size hidden style=... %}`: inline SVG из [library/services/badge_styles.py](library/services/badge_styles.py) — 4 стиля (`emblem` по умолчанию, `hex`, `cartridge`, `shield`), двухцветные иконки `ICONS` там же, цвета — токены `--badge-t1..3-*` / `--badge-single-*`. Стиль выбирает владелец значков в редакторе витрины (`users.badge_style`, NULL — `DEFAULT_STYLE`, поэтому смена дефолта в коде действует на всех, кто не выбирал) и он показывается везде, где видны его значки: передавайте `style=` владельца (`profile_user.badge_style`, `item.user.badge_style` в ленте, `current_library_user.badge_style` в уведомлениях). В тестах проверка после действий выключена (`SITE_ACHIEVEMENTS=False` на `GameVaultTestCase`); новое достижение — добавить в `ACHIEVEMENTS` и метрику в `compute_metrics`. `python manage.py award_site_achievements` — пересчитать всем.

**Волты и магазин** — валюта сайта только зарабатывается (купить за деньги, вывести или передать нельзя). [library/services/volts.py](library/services/volts.py): журнал `volt_transactions` (`VoltTransaction`, `ref_key` уникален для пользователя — за одно действие дважды не начисляется) + кеш баланса `users.volts` в той же транзакции; `grant(user_id, amount, reason, ref_key, daily_cap=...)`, `spend` — условный UPDATE, в минус не уйти. Начисления — там, где действие: уровни достижений GameVault (`sync_site_rewards` в конце `site_achievements.check`, в т.ч. ретро за ранее полученные), закрытая сессия Steam (`close_session`, 1 за 10 мин, лимит в день), достижения Steam, полученные во время сессии (`check_session`; старые из backfill не считаются, редкие <10% дороже), рецензия с текстом от 100 символов (`add_review`, раз на игру, 3 в день), первый визит дня и серия 7 дней (`SteamAutoSyncMiddleware` → `maybe_daily_visit`, кеш; в тестах `VOLTS_DAILY=False`). Суммы и лимиты — константы вверху volts.py, `EARN_RULES` показываются на `wallet/`. Начисления оборачиваются `volts.quietly`, уведомлений о них нет. Магазин — [library/services/shop.py](library/services/shop.py): предметы в коде (`ITEMS`: стили значков `style_cartridge`/`style_shield` — Емблема и Жетон бесплатны, `shop.can_use_style`; рамки аватара — класс `.gv-frame--<ключ>` в gv.css, `user_avatar` берёт `user.avatar_frame`; титулы — фильтр `profile_title`; места витрины `slot_6..8` по очереди — `shop.showcase_size`), купленные/подаренные — `user_items` (`UserItem`, `gifted_by`), надетые — `users.avatar_frame` / `profile_title` / `badge_style`. `buy`/`gift`/`equip`/`unequip` бросают `ShopError` с текстом для пользователя; покупка и подарок — одна транзакция. Подарок — только другу, не для мест витрины и не если предмет уже есть; получатель получает уведомление `gift`, а в ленту событие `gift` пишется, только если дарящий оставил галочку «Показати в стрічці». Страницы: `shop/`, `wallet/` (история), баланс в шапке.

**Интеграция со Steam** находится в [library/services/steam_service.py](library/services/steam_service.py): вход через Steam OpenID (`steam/connect/` → `steam/callback/`), получение профиля и списка игр через Steam Web API и `sync_steam_library`, которая переносит игры в `ExternalLibraryItem` (удаляя пропавшие из Steam) и добавляет совпавшие по `Game.steam_appid` игры в `LibraryEntry` (только новые записи; статусы существующих не меняются; статус новой записи — `steam_status`: играли за 30 дней или есть часы за 2 недели — «Граю», играли раньше — «Відкладено», без часов — «Планую»). Ошибки Steam (нет ключа, сеть, закрытый профиль) выбрасываются как `SteamError` с текстом для пользователя. Требуется `STEAM_API_KEY` в `.env`.

**Каталог пополняется из Steam автоматически** ([library/services/steam_catalog.py](library/services/steam_catalog.py), `import_steam_games` в конце `sync_steam_library`): каждая игра Steam-библиотеки с загруженным `SteamApp` попадает в каталог без заявок — игра каталога без appid с той же нормализованной названием привязывается, иначе создаётся новая (описание, разработчик, дата из Steam Store); жанры берутся из Steam (недостающие жанры каталога создаются, `STEAM_GENRE_ALIASES` для синонимов; ручные жанры не удаляются); игра сразу добавляется в библиотеки всех владельцев, ожидающие заявки на неё одобряются с уведомлением. Не импортируются: `app_type != game`, «программные» жанры (`SOFTWARE_GENRES`), `SteamApp.adult` (content descriptors 3/4), `SteamApp.blocked` (админ удалил игру — `block_appid`; повторное назначение appid в админке снимает блок). Заявки (`GameRequest`) остались только для игр, которых нет у пользователей в Steam. Обложка игры без постера — вертикальный постер Steam CDN по appid (`components/cover.html`). `get_owned_games` объединяет GetOwnedGames (`skip_unvetted_apps=0`) с GetRecentlyPlayedGames — часть бесплатных игр (Dota 2) приходит только оттуда; поэтому при синхронизации пропавшие из списка игры удаляются, только если наиграно меньше `REMOVE_MISSING_BELOW_MINUTES` (2 ч). Кнопка запуска (`components/steam_launch.html`): «Грати» (`steam://run`) только для игранных за 2 недели, иначе «Відкрити в Steam» (`steam://nav/games/details`) — что установлено, сайт знать не может.

Каталог связан со Steam через `Game.steam_appid`: игра с appid автоматически добавляется в библиотеки владельцев (`link_game_to_steam_owners`) при назначении appid (админская форма, страница `manage/steam-matching/`, одобрение заявки) и при синхронизации. Пользователь видит импорт на `steam/library/` (чужой — `users/<id>/steam/`) (игры сами попадают в каталог, см. выше). При одобрении такой заявки и при `?steam_appid=` на админской форме данные и постер подтягиваются из публичного Steam Store API (`fetch_store_details`, `download_steam_poster`). Данные игр Steam Store (точная обложка, жанры) хранятся один раз на appid в `steam_apps` (`SteamApp`): `refresh_steam_apps` догружает до `STEAM_APPS_PER_SYNC` новых игр за синхронизацию, `python manage.py fetch_steam_apps` — все сразу (Steam ограничивает частоту запросов, есть `--delay`). `ExternalLibraryItem.cover_url` берёт `header_image`, если к элементу подгружен `steam_app` (`attach_steam_apps(items)`), иначе CDN по appid (`<img onerror="this.remove()">` на случай отсутствия). Жанры Steam сопоставляются с жанрами каталога по названию (`map_steam_genres`, синонимы в `STEAM_GENRE_ALIASES`) и с весом `STEAM_ONLY_FACTOR` влияют на рекомендации для игр вне каталога.

**Стрічка активности** — [library/services/activity.py](library/services/activity.py) и таблица `activity_events` (`ActivityEvent`). События пишутся во view в момент действия через `activity.record_*` (добавление в библиотеку, смена статуса, оценка, импорт Steam — одно событие на синхронизацию, дружба, одобренная заявка; игровые сессии и достижения Steam пишет не view, а опрос Steam — см. ниже); повторная смена статуса/оценки той же игры в течение `MERGE_WINDOW` сливается в одно событие, удаление игры из библиотеки удаляет её события (`forget_game_activity`). Новое действие, которое должно попасть в ленту, — добавьте `record_*` в соответствующий view и тест в `test_activity.py`. Лента (`feed/`, блок на главной, «Остання активність» в профилях) показывает свои события и события друзей; чужие скрываются, если у автора `User.show_activity = False`. Шаблон одного события — `_feed_item.html` (глаголы в настоящем времени, чтобы не угадывать род пользователя), «Зараз грають» — `_now_playing.html`.

**Шаблоны и статика (дизайн «Картридж»):** все страницы наследуют [base.html](library/templates/library/base.html) (шапка во всю ширину, контент до `--content-max`, тема через `data-theme` на `<html>` + localStorage; там же общий JS: переключатель темы, автосабмит `form[data-autosubmit]`, кнопка «Показати» в `.gv-password`, имя файла в `.gv-file`). Единственный файл стилей — [library/static/library/css/gv.css](library/static/library/css/gv.css): токены тёмной/светлой темы в начале, дальше компоненты `gv-*` (кнопки, чипы, карточки, обложки, списки, формы — `gv-form`, `gv-field`, `gv-switch`, `gv-file`, `gv-chip-check`; `gv-box` и `gv-admin-row` — блоки на фоне `surface-2` внутри `gv-card`, `gv-np-card` — карточка Steam-игры с горизонтальной обложкой, `gv-state--*` — статус заявки, лента, рекомендации, профиль). Новые цвета — только через токены, чтобы работали обе темы. Второстепенные действия — круглые кнопки-иконки `gv-btn gv-btn--icon` (+ `gv-btn--sm`) с `title` и `aria-label`, иконки — тег `{% icon "sync" %}` (набор `ICONS` в `library_extras`), основное действие — кнопка с текстом; ряд «кнопка + иконки» — `gv-actions`. Сетки, которые не должны оставлять пустые места в последнем ряду, используют фиксированное число колонок под размер страницы (`gv-steam-grid` 1/2/3/5/6 при `STEAM_LIBRARY_PAGE_SIZE = 30`; `gv-grid-24` 2/3/4/6/8 при `GAMES_PAGE_SIZE` и `LIBRARY_PAGE_SIZE` = 24 — каталог и библиотеки; `gv-grid-6` для 6 элементов). Компоненты-теги в `library_extras`: `game_cover`, `user_avatar`, `score_ring`, `pagination`, `url_with`, `nav_active`, `icon`, `static_v` (URL статики с версией по mtime), фильтры `day_label`, `cover_bg/cover_ink`; переиспользуемые фрагменты в `templates/library/components/` и `_feed_item.html`, `_profile.html`. `test_pages.py` проверяет, что все служебные страницы рендерятся. Страницы ошибок: `library/templates/404.html` (наследует base.html) и `500.html` (самостоятельная, без контекста и БД); видны только при `DEBUG = False`. При замене аватара/постера и удалении игры старый файл удаляется через `storage.delete_unused_file` (если на него никто больше не ссылается); постеры по адресу из формы скачиваются только с HTTPS-хостов Steam (`is_steam_image_url`). Загружаемые пользователями файлы (аватары, постеры игр) сохраняются в `media/` и раздаются Django только при `DEBUG = True`.
